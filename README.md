# SlideDeckCreator

日本語の記事・メモ・URL・過去の登壇資料から、**伝わるLTスライド**を作るためのCodex Skills集です。

ストーリー設計、スライド設計、画像準備、HTML/PDF生成、実ブラウザでのレビュー、ブラウザ内編集までを、段階的なパイプラインとして扱います。

> [!NOTE]
> このリポジトリは個人制作のプロジェクトであり、OpenAI公式プロジェクトではありません。

## 特徴

- 完成記事では、原稿の見出し順を保つ `section-faithful` モードを使用
- 原則として **1セクション＝1スライド** で対応関係を維持
- セクション本文からページ固有の `Spoken Note` を先に作ることで、説明内容とスライド内容が一致する設計
- 1280×720のHTMLスライド、発表者ビュー、PDF、配布ZIPを生成
- 生成後のHTMLをブラウザ上で編集し、HTML/PDFへ再保存できる
- 単発LTと複数回シリーズの両方に対応できる

30分登壇資料もAIへの指示は一瞬で、AIの作業時間30分で作成できます。

## 必要な環境

- Codex Desktop、Codex CLI、またはCodex IDE extension
- Python 3.11以降
- Node.js 18以降
- ChromeまたはPlaywright Chromium

Codex Desktopの同梱ランタイムを利用できる場合、Node.jsやPlaywrightは自動探索されます。単独のローカル環境で検証スクリプトを動かす場合は、次の依存関係を用意してください。

```bash
python -m pip install pyyaml pypdf
npm install --no-save playwright
npx playwright install chromium
```

画像生成が必要なスライドでは、利用中のCodex環境で画像生成機能が使える必要があります。画像生成を使わず、提供画像やHTML/SVG図解だけで構成することもできます。

## 入力を準備する

原稿と画像は `input/` 配下へ置きます。`input/` はGit管理対象外です。

```text
input/
├─ article.md
└─ assets/
   ├─ diagram.png
   └─ screenshot.png
```

発表者情報は `config/presenter.json`、話し方や構成の傾向は `config/slide-style-profile.md` で管理します。

```text
config/
├─ presenter.json
└─ slide-style-profile.md
```

`presenter.json` には表示名、自己紹介、SNS、アバター、QR画像を設定できます。クローン後は、作者の情報やローカル絶対パスを自分の環境に合わせて変更してください。

## 原稿の扱い

### section-faithful

見出し構造を持つ完成記事に使用します。

- 原稿のセクションと順番を維持
- 1セクションを原則1スライドへ割り当て
- セクション本文を、そのページで話す内容の根拠として使用
- 長いセクションを短縮する場合は、短縮範囲と理由を記録
- 原稿セクション、Story、Blueprint、HTMLの対応を検証

### narrative-recompose

断片的なメモ、複数資料、トピックだけの入力に使用します。

- 発表の問いと学習ゴールから物語を再構成
- 入力の事実と新しく組み立てた説明を区別
- 根拠のない経験談や成功結果を追加しない

## Spoken Note

各ページの台本は、次の4区画を基本とします。

```text
橋渡し: 前ページからこのページへ進む理由
話す内容: 実際に口にする説明
指差し: スライド上で注目させる場所
次の一言: 次ページへつなぐ発話
```

投影面の文章をそのまま読み上げるのではなく、背景、具体例、読み方、判断理由をSpoken Noteへ分離します。

## 操作モード

ここでいう操作モードは、原稿変換時の `section-faithful` / `narrative-recompose` とは別の、生成後のHTMLを表示・操作する状態です。

| モード             | 開き方                                              | 用途と状態                                                                                                        |
| ------------------ | --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 通常表示モード     | `index.html`                                        | 投影・発表・後日閲覧用。スライド移動、段階表示、ページ一覧、全画面表示を操作する                                  |
| 発表者ビューモード | `index.html?presenter=1` または通常表示モードで `S` | 現在・次のスライド、Spoken Note、問い、タイマーを手元に表示し、投影側と双方向同期する                             |
| 編集モード         | `index.html?edit=1` または通常表示モードで `E`      | 要素、テキスト、Spoken Note、画像、吹き出し、ページを編集し、HTML/PDFへ保存する。`V` で編集UIだけを一時的に隠せる |

### モード内の一時状態・機能

次の項目は独立した操作モードではなく、上記3モードの中で利用する一時状態、検証オプション、または出力機能です。

| 状態・機能     | 開き方                                      | 所属と用途                                                                                                  |
| -------------- | ------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| ページ一覧     | 通常表示モードまたは編集モードで `P`        | 全ページのサムネイルを表示し、appendix・referenceを含む任意ページへ移動する。発表者ビューモードでは開かない |
| 全画面表示     | 各モードで `F`                              | 現在のブラウザウィンドウを全画面化する。元のモードと操作方法は維持される                                    |
| 編集UI非表示   | 編集モードで `V`                            | 編集URLを維持したまま編集UIと編集操作を隠し、段階表示やページ送りを確認する。もう一度 `V` で編集UIを戻す    |
| レイアウト監査 | `index.html?audit=1`                        | 通常表示モードの読み込み時にレイアウト検証を実行するQAオプション。専用ショートカットはない                  |
| 印刷・PDF出力  | ブラウザ印刷または編集モードの `Export PDF` | 編集UIを除外し、全アニメーションstepを表示した16:9ページとして出力する。対話操作は行わない                  |

`section-faithful` かつ `dual-use` のデッキでは、通常の「次へ」操作は本編最後のThanksで停止します。appendix・referenceはページ一覧、または `#<ページ番号>` の直接リンクから開きます。

### 編集サーバー

HTMLやPDFを同じファイルへ上書き保存する場合は、ローカル編集サーバーを起動します。

```bash
node .codex/skills/06-lt-slide-editor/scripts/serve_editor.js output/index.html
```

表示された `http://127.0.0.1:4177/?edit=1` を開いて編集します。

#### 一時状態・機能での扱い

- 編集UIを `V` で隠している間も編集モードです。要素移動・削除だけが無効になり、`→`、`←`、`Space`、`PageDown`、`PageUp` などの閲覧操作はそのまま使えます。
- ページ一覧を開いている間は `P` または `Escape` で閉じます。開く前のモードに属する移動・リプレイ・全表示・全画面のショートカットも有効です。
- 全画面表示中は `F` で解除します。それ以外のショートカットは、全画面表示を開始したモードの一覧と同じです。
- `?audit=1` は通常表示モードへレイアウト監査を追加するURLオプションです。読み込み後のショートカットは通常表示モードと同じです。
- 印刷・PDF出力にはキーボードショートカットがありません。

テキスト、Spoken Note、入力欄、セレクトボックス、`contenteditable` 要素へ入力している間は、文字編集を優先するためショートカットを実行しません。`E`、`V`、`P` は `Ctrl`、`Alt`、`Command`、`Shift` などの修飾キーを付けずに押してください。

## 品質検証

パイプラインでは、次の観点を自動または実ブラウザで検証します。

- 原稿セクションとスライドの一対一対応
- 知識単位、出典、表、コード、設定、図の追跡可能性
- 見出し・主張の主語、行為者、変更対象、述語
- Spoken Noteの構造とページ固有性
- 発表時間とページごとの説明量
- レイアウトの見切れ、重なり、余白不足
- アニメーション完了状態と段階表示
- 発表者ビューの台本、問い、タイマー、スクロール
- PDFのページ数と16:9サイズ
- 編集UIが通常表示、発表者表示、印刷を壊していないこと

代表的な検証コマンドは次のとおりです。

```bash
python .codex/skills/02-lt-slide-blueprint/scripts/validate_blueprint.py .lt-slide-work/02-blueprint.yaml
python .codex/skills/04-lt-slide-build/scripts/validate_deck.py output/index.html
python .codex/skills/04-lt-slide-build/scripts/validate_pdf.py output/index.pdf output/index.html
node .codex/skills/05-lt-slide-review/scripts/review_deck.js output/index.html --story .lt-slide-work/01-story.yaml --blueprint .lt-slide-work/02-blueprint.yaml --out .lt-slide-work/review
```
