# 発表で使う言葉とノート

2026-09-05の発表者の明示的な希望。過去資料から抽出した傾向より、この希望を優先する。

- 新しく書く見出し、図のラベル、説明文、ノートでは、抽象的な比喩として「正本」「地図」「道具」を使わない。指すものに応じて「更新先を一つに決めた設計資料」「機能とファイルの対応表」「依存関係図」「テスト用スクリプト」「開発環境」などと書く。
- 別の比喩に置き換えず、ファイル、機能、操作、結果を具体的に示す。「知識経路」「証拠」なども、参照するファイルや実行ログのことならその名前で説明する。
- 引用、正式名称、コードの識別子、地理の説明は意味を変えない。必要な例外はスライドの `language_exceptions: [{term: ..., reason: ...}]` に記録できる。入力原文の語を理由に、新しい説明へ比喩を増やさない。
- 記事を読み上げる前提にしない。画面で分かる部分を決めてから、そのページで補う理由・経験・判断だけを話す。発表者が話していない経験や感情は作らない。
- ノートは短い要点メモを基本にする。必要なページだけ発話例を併記する。毎ページに導入・振り返り・次ページ予告を足さない。
- 反復には目的が必要。同じ表を再表示するときは、前に説明した箇所と今回追加する説明を区別する。まとめは基本的に「発表した内容」の主要な要点・関係・結論を振り返る。新しい課題や「明日やること」で内容の要約を置き換えない。行動提案は必要な場合だけ、まとめとは区別して扱う。（2026-09-26の希望を反映）
- AIによる確認と、発表者本人が声に出した確認は別々に報告する。資料やブレインマップから本人の話し方を完全に再現したとは扱わない。
