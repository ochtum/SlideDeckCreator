# Extraction Criteria

資料ごとに特徴を観察し、`scope` と `status` の2軸で分類する。単純な出現件数だけで恒常ルールへ昇格させず、テーマ、発表時期、シリーズ、テンプレートの独立性も評価する。

## Observation Areas

| Area | Observe | Convert to a rule only when |
| --- | --- | --- |
| Presenter stance | 専門家・実験者・伴走者のどこから話すか | 独立した複数資料で同じ立ち位置が確認できる |
| Narrative | 疑問、条件、試行、失敗、発見、結果、実務評価の順序 | 順序が学習効果や理解の流れに寄与している |
| Headings | 説明、問い、独り言、感情、結論、転換の比率 | 文型、目的、使う場面、使わない場面を説明できる |
| Voice | 文末、文長、疑問符、感嘆符、三点リーダー、呼びかけ | 使用場面と上限を定義できる |
| Emotional beats | curiosity、skepticism、challenge、failure、discovery、success、reflection | 前後の具体的な情報と結び付いている |
| Specificity | 数値、制約、時間、ファイル、コード、エラー、成果物 | 同じ種類の具体物を複数資料で優先している |
| Composition | 1カラム、左右分割、中央配置、全面画像、カード | 複数資料で同じ目的に使われている |
| Density | 文字量、余白、要素数 | 高密度・低密度の使い分けが説明できる |
| Hierarchy | タイトル、本文、結論、補足、出典の強弱 | 情報の優先順位として再現できる |
| Emphasis | 色、サイズ、太字、囲み、矢印 | 強調対象と使用場面が明確である |
| Asset usage | スクリーンショット、コード、表、図、アイコン、生成画像 | 素材選択に一貫した傾向がある |
| Transition slide | 問い、感情、章区切り、結論だけのページ | 前後のページとの役割が説明できる |
| Repetition | 同じレイアウト、装飾、記号の連続 | 使用上限または回避条件を定義できる |
| Pacing | 高密度・低密度ページの並び | 発表全体の理解、間、期待形成に寄与している |
| Reader flow | 前ページから次ページへの意味の接続 | 橋渡しや次の問いが再現可能である |
| Speaker notes | 画面外で補う背景、判断、前後接続 | 台本または話者ノートを確認できた |
| Spoken transitions | ページ末尾の一言、次の問いの立て方、指差しながら話す順序 | 台本・録画・ノートで実際の発話を確認できた |

## Classification Axes

特徴は `scope` と `status` を分けて分類する。

### Scope

- `shared`: 独立した複数資料で確認できる。
- `candidate`: 根拠はあるが、恒常ルールには不足する。
- `deck-specific`: 特定資料または同一シリーズ内にのみ現れる。
- `unknown`: 必要なテキスト、視覚、ノートを取得できない。

### Status

- `stable`: 複数テーマ・複数時期で継続している。
- `emerging`: 最近の複数資料で増えている。
- `contextual`: 特定テーマ、シリーズ、テンプレート、発表時間でのみ有効。
- `deprecated`: 過去には存在したが、現在は適用を推奨しない。

`scope` と `status` は組み合わせて使う。

```yaml
scope: shared
status: contextual
```

これは、複数資料で確認できるが、特定条件でのみ使う特徴を表す。

## Evidence Independence

根拠の強さは単純な資料数ではなく、次を確認して判断する。

- `occurrences`: 確認できた出現回数
- `distinct_topics`: 異なるテーマ数
- `distinct_periods`: 異なる発表時期
- `series_dependency`: 同一シリーズへの依存度
- `template_dependency`: 同一テンプレートへの依存度
- `confidence`: `high`、`medium`、`low`

### Decision Rules

- 3資料以上かつ、異なるテーマまたは異なる発表時期で確認できる場合: `shared` の候補とする。
- 2資料で確認できる場合: `candidate` とし、原則として `SHOULD` または `MAY` に限定する。
- 1資料だけの場合: `deck-specific` とし、恒常ルールへ昇格させない。
- 同一シリーズ、同一テーマ、同一テンプレート内の繰り返し: 出現回数には含めるが、独立した根拠として過大評価しない。
- 最近の複数資料でのみ確認できる場合: `emerging` 候補として扱う。
- 特定テーマ、発表時間、シリーズでのみ成立する場合: `contextual` として扱う。
- 過去には確認できるが現在の品質基準では推奨しない場合: `deprecated` 候補として扱う。
- 視覚情報や話者ノートを取得できない場合: 該当領域を `unknown` とし、補完や推測をしない。
- テーマや発表目的だけで説明できる特徴: `deck-specific` または `contextual` とする。
- 新しい資料1件だけで、複数資料に支えられた `stable` ルールを上書きしない。

## Observation And Application

過去資料での観察と、今後の適用方針を分離する。

### Observation

```yaml
observation:
  description: 問題発生時に短い独立スライドを使用する
  occurrences: 5
  distinct_topics: 3
  distinct_periods: 2
  confidence: high
```

### Interpretation

```yaml
interpretation:
  role: failure-transition
  purpose: 問題の発生を明確にし、原因調査へ切り替える
```

### Application

```yaml
application:
  strength: SHOULD
  applies_when: 実際の検証で重要な想定外が発生した場合
  guidance: 問題の存在を短く示し、次のスライドで原因または再試行を示す
  next_slide: 原因、エラー、または次に試した操作
  limits:
    max_ratio_of_main_slides: 0.15
    max_consecutive_usage: 1
    min_distance_between_uses: 3
```

### Application Decision Rules

- 観察頻度と適用強度を同一視しない。
- 頻出表現でも、可読性や現在の品質基準に合わない場合は `MAY` または `MUST NOT` とする。
- 過去によく使っていたことだけを理由に `MUST` へ昇格させない。
- 表現の目的、使わない条件、頻度上限を説明できない特徴は再利用ルールにしない。
- `MUST` は、独立性のある複数資料で確認でき、発表者らしさの中心である場合に限定する。
- `MUST NOT` は、事実捏造、過剰適用、技術的不正確さ、可読性低下を防ぐ場合に使用する。

## Surface Separation

次の表現面を分けて分析する。

- 発表タイトル
- 章タイトル
- 通常スライド見出し
- 転換スライド
- 投影面の本文
- 話者ノート

### Rules

- 発表タイトルは検索性と内容理解を優先する。
- 会話的・感情的な表現は、主に通常見出しと転換スライドで評価する。
- 話者ノートの独り言や補足説明を、そのまま投影面の長文へ適用しない。
- 話者ノートは、前ページからの橋渡し、実体験、判断理由を中心に評価する。
- 話者ノートや録画がない場合、投影面の順序から実際の台詞、話速、指差し対象を推測しない。該当領域は `unknown` とする。
- 抽出した話し方は `question_spine` やページ固有台本を自動生成する代用品にしない。新しいテーマの問い・答え・実演は、そのテーマの入力から01で設計する。

## Negative Pattern Criteria

使う表現だけでなく、発表者の傾向と合わない表現も必要に応じて記録する。

対象例:

- 抽象的な企業表現
- 根拠のない煽り
- 経験していない成功談や失敗談
- 内容を過度に三項カードへ整理する表現
- 具体的な根拠を削って雰囲気だけを残す表現
- 感嘆符、顔文字、statementの機械的な反復

### Rules

- 過去資料に少ないことだけを理由に禁止しない。
- 発表者の立ち位置や複数資料の傾向と矛盾する場合だけ記録する。
- 技術用語や正式名称は、過去資料に少ないことを理由に禁止しない。
- `MUST NOT` の根拠が安全方針や品質方針の場合は、通常の出現回数とは別に `evidence_basis` を記録する。

## Safety Checks

- 表現のために、実際には起きていない失敗、驚き、成功、感情を追加しない。
- スタイルが技術的正確性、初見者への定義、具体物の可読性を下回らないようにする。
- 既存資料の固有フレーズを繰り返しコピーしない。役割と条件を抽象化する。
- 視覚情報を取得できない資料から、配色、余白、レイアウト、ペーシングを推測しない。
- 同一テンプレート由来の見た目を、発表者固有の視覚スタイルとして過大評価しない。
- 発表時間が短いほど、雰囲気だけのページより、具体例、結果、判断基準を優先する。

## Duration Conditioning

- `duration_minutes` が不明な資料から、ページ当たりの情報量、ページ送りの速度、statement比率、話者ノート量を推測しない。
- 5〜10分資料の低密度ページは、短時間で注意を切り替えるための `contextual` な表現として扱う。
- 20分以上へ適用するdensity/pacingルールは、20分以上の根拠資料がある場合だけ発表者固有ルールへ昇格させる。
- 長時間資料の根拠がない場合は、問い、短文、巨大タイトルの比率を増やさず、具体例、仕組み、比較、デモ、判断基準を優先する品質既定値へ戻す。
- 同じ発表者でも、短時間LTと長時間セッションは別の密度モードとして記録する。
